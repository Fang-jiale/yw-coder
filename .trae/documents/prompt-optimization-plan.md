# Prompt 优化方案：解决 AI 输出截断导致 JSON 解析失败

## 问题根因

AI 生成代码过长，触发了 `max_tokens` 限制，导致：
1. JSON 字符串输出不完整（字符串未闭合）
2. `JSON.parse()` 解析失败
3. 函数调用无法执行

**证据**：
- `arguments 长度: 16175` 字符
- 截断位置在代码中间：`document.querySelectorAll('.feature, .cta-button, .`

## 问题分析

当前 System Prompt 存在的问题：
1. **过长**：包含 16 个章节（角色定义、能力范围、输出格式、任务管理、错误处理、上下文管理、最佳实践、代码审查、安全最佳实践、性能优化等）
2. **冗余示例**：包含多个 Few-shot 示例，占用大量 token
3. **缺少输出长度约束**：没有明确告知 AI 需要控制输出长度

估算当前 System Prompt 长度：**约 2500-3000 tokens**

## 优化方案

### 方案目标
在不增加 `max_tokens` 的前提下，通过优化 prompt 减少系统占用，增加 AI 输出可用空间。

### 具体步骤

#### Step 1: 精简 System Prompt
**修改文件**: `src/main/services/aiStreamService.ts`

**精简策略**:
- 移除重复的示例（保留 1 个核心示例）
- 合并相似章节
- 删除过于细节的指导原则

**精简后的 Prompt 结构**（约 800-1000 tokens）:
```
# 角色定义
你是 ywcoder，专业的智能编程助手。

## 核心能力
- 搜索和读取项目文件
- 创建和修改文件（使用 file 标签）
- 管理任务进展（使用 todo 标签）
- 主动提问澄清需求（使用 question 标签）

## 输出格式
1. 文件操作：使用 <file path="路径">内容</file>
2. 任务管理：使用 <todo><task> 标签
3. 提问：使用 <question><option> 标签

## 工作流程
1. 理解需求 → 2. 分析现状 → 3. 规划任务 → 4. 执行操作 → 5. 总结

## 重要约束
【输出长度控制】AI 必须控制输出长度：
- 单次文件写入不超过 500 行
- 如果代码超过 500 行，先写核心框架，用 <question> 询问是否继续
- 保持 JSON 格式完整，不要截断字符串

## 示例
用户：创建登录功能
...
```

#### Step 2: 添加输出长度控制指令
在 System Prompt 末尾添加：
```
## 输出长度控制

【关键】AI 输出受限于上下文窗口，必须控制每次输出的长度：

1. **文件写入限制**：
   - 单次 <file> 标签内容不超过 500 行
   - 如果预估代码超过 500 行，先写核心部分，用 <question> 询问后续

2. **保持 JSON 格式完整**：
   - 所有字符串必须正确闭合（使用单引号或双引号）
   - 检查 <file> 标签的 path 属性是否正确闭合
   - 避免在字符串中间截断

3. **分步执行**：
   - 复杂任务分多次完成
   - 每次只写一个文件或一个模块
   - 用 todo 标签标记未完成的部分
```

#### Step 3: 移除冗余章节
删除以下章节（保留核心概念）：
- ❌ 代码审查指导（合并到最佳实践）
- ❌ 安全最佳实践（合并到最佳实践）
- ❌ 性能优化（合并到最佳实践）
- ❌ 工具使用策略（合并到工作流程）
- ❌ 过多示例（保留 1 个）

## 预期效果

| 指标 | 优化前 | 优化后 |
|------|--------|--------|
| System Prompt 长度 | ~2500 tokens | ~800 tokens |
| 可用输出空间 | ~1500 tokens | ~3200 tokens |
| 代码输出安全长度 | ~300 行 | ~600-800 行 |
| JSON 截断风险 | 高 | 低 |
