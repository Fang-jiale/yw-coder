# 思考过程标签暴露问题排查结论（修订版）

## 问题现象
- 第一段 assistant 输出时，思考过程可以被折叠显示
- 后续流式输出中，`<think>`、`<todo>`、`<task>` 等内部协议文本直接出现在正文区域

## 真正的问题根因

### 问题 1：`filterToolCalls` 没有过滤 <think> 标签

`src/main/services/aiStreamService.ts` 中的 `filterToolCalls` 方法**没有过滤 <think> 标签**：

```typescript
// 有这些过滤：
.replace(/<todo>[\s\S]*?<\/todo>/g, '')
.replace(/<task\s+[^>]*>[\s\S]*?<\/task>/g, '')

// 但缺少：
// .replace(/<think>[\s\S]*?<\/think>/g, '')
```

### 问题 2：正则表达式写错

`src/shared/types.ts` 中的 `parseMessageContent` 函数正则写错：
- AI 输出：`<think>` 和 `</think>`（有字母 n）
- 正则写成：`<\\/think>`（没有字母 n）
- 导致永远匹配不到

## 为什么"第一段输出可以折叠"

因为 aiStreamService 使用**状态机**处理 <think> 标签：
1. 检测到 `<think>` 时，设置 `inThinkBlock = true`
2. 积累内容直到遇到 `</think>`
3. 通过 `callback({ type: 'thinking', content: ... })` 发送思考内容
4. 通过 `callback({ type: 'content', content: ... })` 发送清理后的正文

所以**首次**思考能被正确处理。

## 为什么"后续流式输出暴露标签"

当状态机处理失败时（如跨 chunk 边界、多重嵌套等情况），`filterToolCalls` 会尝试兜底过滤，但它**没有过滤 <think> 标签**，导致标签暴露。

## 修复方案

### 修复 1：在 `filterToolCalls` 中添加 <think> 过滤

在 `aiStreamService.ts` 的 `filterToolCalls` 方法中添加：
```typescript
// 过滤思考标签
.replace(/<think>[\s\S]*?<\/think>/g, '')
```

### 修复 2：修复 `parseMessageContent` 的正则表达式

将 `<\\/think>` 改为 `<\/think>`（添加字母 n）

## 已实施的修复
- ✅ 修复了正则表达式（types.ts）

## 待实施的修复
