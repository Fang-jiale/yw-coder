## 4. trimHistoryMessages() 是否做语义压缩？

### 核查结果：✅ **被调用，但仅简单截断**

### 代码实现

[aiStreamService.ts#L115-139](file:///Users/sijia/code/git_program/yw-coder/src/main/services/aiStreamService.ts#L115-L139)：

```typescript
function trimHistoryMessages(
  messages: Message[],
  maxTokens: number,
  systemPromptLength: number
): Message[] {
  const availableTokens = maxTokens - systemPromptLength - TOOL_RESULT_RESERVE;
  let currentTokens = 0;
  const trimmedMessages: Message[] = [];

  // 从后往前遍历，保留最近的消息
  for (let i = messages.length - 1; i >= 0; i--) {
    const msg = messages[i];
    const msgTokens = estimateTokens(msg.content || '');

    if (currentTokens + msgTokens > availableTokens) {
      break;  // 直接丢弃，不做压缩
    }

    trimmedMessages.unshift(msg);
    currentTokens += msgTokens;
  }

  return trimmedMessages;
}
```

### 调用位置

[aiStreamService.ts#L742](file:///Users/sijia/code/git_program/yw-coder/src/main/services/aiStreamService.ts#L742)：
```typescript
const trimmedHistory = trimHistoryMessages(historyMessages, contextLength, systemPromptLength);
```

### 行为分析

| 特性 | 实现方式 |
|------|----------|
| 压缩方式 | **无语义压缩**，仅截断 |
| 截断策略 | 从旧到新，**保留最近的消息** |
| Token 估算 | 简单按字符数/4 估算 |
| 信息损失 | **旧消息完全丢弃**，无任何保留 |

### 结论

**trimHistoryMessages() 确实被主流程调用**，但只是**最简单的截断策略**：
- 优点：实现简单、计算快速
- 缺点：较早的对话信息完全丢失

**没有做语义压缩**，不保留摘要或关键信息。

## 5. read_file(offset, limit) 是否真正局部读取？

### 核查结果：⚠️ **被调用，但不是真正的局部读取**

### 代码实现

[aiToolService.ts#L335-352](file:///Users/sijia/code/git_program/yw-coder/src/main/services/aiToolService.ts#L335-L352)：

```typescript
private async readFile(filePath: string, offset?: number, limit?: number): Promise<ToolResult> {
  const fullPath = path.join(this.workspacePath, filePath);
  let content = await fs.readFile(fullPath, 'utf-8');  // ← 始终读取全文

  // 如果指定了行范围
  if (offset !== undefined || limit !== undefined) {
    const lines = content.split('\n');  // ← 全文按行分割
    const start = offset || 0;
    const end = limit ? start + limit : lines.length;
    content = lines.slice(start, end).join('\n');  // ← 内存中选取区间
  }

  return {
    tool: 'read_file',
    success: true,
    data: { content, file_path: filePath },
  };
}
```

### 实际流程

```
fs.readFile(fullPath, 'utf-8')  ← 始终读取全文
        ↓
content.split('\n')              ← 全文按行分割
        ↓
lines.slice(start, end)          ← 内存中选取区间
        ↓
join('\n')                       ← 重新组合返回
```

### 关键发现

1. **offset/limit 参数确实被使用** - AI 可以请求特定行范围
2. **但不是真正的局部读取** - 文件仍被完整读入内存
3. **无流式读取实现** - 全代码库无 `createReadStream` 使用

### 结论

**offset/limit 是"先读全再切片"**，不是真正的按需读取。
